## English

Brazilian Portuguese fan translation of *Maid Cafe on Electric Street*. The translated text replaces the game's English text directly in `resources.assets` (and, for a few lines written in the code, in `global-metadata.dat`). No mod loader is required.

### Installing (players)

1. Download the zip for your system from [Releases](https://github.com/Kaironn2/maid-cafe-loc/releases/latest): Windows, Linux / Steam Deck (Proton) or macOS (CrossOver/Whisky).
2. Close the game, extract the zip and open `MaidCafe-PTBR`.
3. It finds the game in Steam by itself. If it can't, it opens a window to pick the game folder.

To uninstall, open it again and choose "Restaurar" (restore). The `LEIA-ME.txt` in the zip has the details for each system.

### Repository layout

```
translations/          ← WHERE TRANSLATION HAPPENS (edit only the "PT" field)
  texts/               menus, names, items, short NPC lines
  scenes/              story dialogue (one scene per file)
  extras/              random NPC lines, CG gallery, credits
  excel/               prologue and day 1 dialogue stored as spreadsheets
  code/                dialogue written directly in the game code (global-metadata.dat)
  glossary.md          official glossary: how each recurring term is translated
tools/maidloc/         extract / sync / patch tool (Go)
tools/check/           validators for translation files and text encoding
tools/translation-rules.md  rules for translators and translation agents
resources/             reference generated by extract, do not edit by hand
  extracted/           every original JSON from the game (languages/, scenes/, excel/, code/, data/)
  map.json             asset map: languages, format, fields, text counts
```

### Translation file format

Every game text has the **English original** (`EN`) and a slot for the **Portuguese** (`PT`):

```json
"StartNewGame": {
  "PT": "Novo Jogo",
  "EN": "New Game"
},
```

In scenes, each line also shows who is speaking, to help keep the voice consistent:

```json
"1": {
  "Personagem": "Miyu",
  "PT": "",
  "EN": "Hiii! One meat bun please!"
},
```

- **Edit only `PT`.** Do not change `EN`, `Personagem` (speaker), or the keys (`"1"`, `"StartNewGame"`).
- An empty `PT` means "not translated yet". In game, that text stays in English.
- `(narração)` (narration) and `(protagonista)` (protagonist) are speakers with no on-screen name. A few speakers still show the game's internal code (for example, `suinaixiang`).

### Translation rules

1. **Keep the markup.** The patcher warns when it doesn't match the English.
   - `{0}` and `{1}` are values the game inserts. Example: `"earn [{0}] yen"` → `"ganhar [{0}] ienes"`.
   - `<color=blue>text</color>` is a color tag. Keep the tags and translate only the text between them.
   - `\n` is a line break. Keep about the same number, because the dialogue box has a fixed width.
2. **Valid JSON.** Quotes inside a text become `\"`. Don't delete commas or braces. If a file breaks, the patcher shows the file and line of the error.
3. **Save as UTF-8.** Accented characters are fine.
4. **Menu texts have little room.** Prefer short versions.
5. **Use the same names and terms everywhere** (Shiro, Miyu, Favna, Senpai, Kohai...). Check `translations/glossary.md` and the existing translations before choosing a word.
6. **Validate before committing:** `node tools/check/check.js <file>` checks encoding, placeholders, tags and line breaks.

### The `maidloc` tool

Requires Go. Run it from the repository root:

```
go run ./tools/maidloc <command>
```

To skip compiling on every run, build an executable: `go build -o maidloc.exe ./tools/maidloc` (`.exe` files are git-ignored).

| Command | What it does |
|---|---|
| `status` | Shows translation progress per file and per folder (`-v` lists every file). |
| `patch` | Reads the `PT` field from `translations/` and writes it into the right game assets and keys. Without `-apply`, it only does a dry run and prints warnings. |
| `extract` | Reads the game and regenerates `resources/extracted/` and `resources/map.json`. Only needed after a game update. |
| `sync` | Creates or updates the files in `translations/` from `resources/extracted/`. **Keeps all existing PT.** If the English of a translated text changed, it flags it as `REVISAR` (review). |

Common options: `-game "<*_Data folder>"`, if the game isn't in the default Steam folder, and `-dir <folder>` to use another translations folder.

#### Testing the translation in game

```
go run ./tools/maidloc patch            # dry run: lists what would be applied, plus warnings
go run ./tools/maidloc patch -apply     # writes to the game (close the game first)
```

Then start the game with the **English** language selected.

How the patch works:
- It always starts from the **original** files, `resources.assets.bak` and `il2cpp_data/Metadata/global-metadata.dat.bak`, which are created on the first apply. You can run it as many times as you like: the file doesn't grow and old translations don't pile up.
- Only texts with a filled-in `PT` change. Everything else stays identical to the original (verified).
- **To undo:** copy each `.bak` over its file (`resources.assets`, `global-metadata.dat`), or use "Verify integrity of game files" in Steam.

#### When the game updates

1. In Steam, run "Verify integrity" to get clean files, then delete the old `resources.assets.bak` and `global-metadata.dat.bak`.
2. `go run ./tools/maidloc extract`
3. `go run ./tools/maidloc sync`: review the texts flagged `REVISAR` (English changed) and `ÓRFÃ` (text removed from the game).
4. `go run ./tools/maidloc patch -apply`

### Publishing a release

The player installer is `maidloc` itself, built with `translations/` embedded (`embed.go`). Run without arguments, it runs `install`: it looks for the game in the Steam libraries (registry and `libraryfolders.vdf` on Windows, the usual Steam folders on Linux, CrossOver/Whisky bottles on macOS), and if it doesn't find it, opens the system's folder picker (Win32 API on Windows, `osascript` on macOS, `zenity`/`kdialog`/`yad` on Linux) or asks for the path in the terminal.

```
go run ./tools/release v1.0.0    # local build: dist/*.zip and dist/SHA256SUMS.txt
git tag v1.0.0 && git push origin v1.0.0
```

Pushing a `v*` tag runs `.github/workflows/release.yml`, which builds the zips and creates a **draft** release with them. Review it on GitHub and publish it.

### How it works

The game stores most of its texts as JSON TextAssets inside `resources.assets`, in two formats (details in `resources/map.json`):

- **Per language** (`format: dict`): one asset per language (`ui_cn`, `ui_jp`, `ui_en`, `ui_tc`), each shaped as `{key: text}`. We translate the `*_en` asset.
- **Per row** (`format: rows`): one asset with every language on each row (`StoryText`=cn, `JP`, `EN`, `TC`; or `CnText`/`JpText`/`EnText`/`TcText`; or `LKName`/`JpName`/`EnName`). We translate the English field.

`patch` reads the original asset, replaces the English field with `PT` for each filled-in key, writes the asset at the end of `resources.assets`, and points the object table at the new asset.

The prologue and some day 1 scenes are not JSON: they are spreadsheets imported from `Assets/Resources/GameData/Excel/*.xls` and stored as MonoBehaviours, with 11 text columns per row (id, speaker, cn, jp, en, tc and five more). `maidloc` reads them as `rows` assets named `excel_<sheet>` and translates column `EN`. Each sheet exists twice in `resources.assets`, and `patch` writes both copies. Repeated ids get the keys `13#2`, `13#3`; a row whose English differs in the second copy gets its own key, `119@2`.

A few lines are written directly in the C# code, for example "Your work is not done." when you try to leave the office early. IL2CPP keeps these string literals in `il2cpp_data/Metadata/global-metadata.dat`. Only the literals listed in `tools/maidloc/literals.json` are translated: each text is stored once and shared by all the code, so the list holds only displayed texts that the code never compares. `patch` writes the new text at the end of the file and points the literal table at it. It keeps a `global-metadata.dat.bak` the first time, like `resources.assets.bak`.

### Como funciona por dentro

O jogo guarda a maior parte dos textos como TextAssets JSON dentro de `resources.assets`, em dois formatos (detalhes em `resources/map.json`):

- **Por idioma** (`format: dict`): um asset por língua (`ui_cn`, `ui_jp`, `ui_en`, `ui_tc`), cada um no formato `{chave: texto}`. Traduzimos o `*_en`.
- **Por linha** (`format: rows`): um asset com todas as línguas em cada linha (`StoryText`=cn, `JP`, `EN`, `TC`; ou `CnText`/`JpText`/`EnText`/`TcText`; ou `LKName`/`JpName`/`EnName`). Traduzimos o campo inglês.

O `patch` lê o asset original, troca o campo inglês pelo `PT` em cada chave preenchida, grava o asset no fim do `resources.assets` e aponta a tabela de objetos para o asset novo.

O prólogo e algumas cenas do dia 1 não são JSON: são planilhas importadas de `Assets/Resources/GameData/Excel/*.xls` e guardadas como MonoBehaviours, com 11 colunas de texto por linha (id, personagem, cn, jp, en, tc e mais cinco). O `maidloc` lê cada uma como um asset `rows` chamado `excel_<planilha>` e traduz a coluna `EN`. Cada planilha existe duas vezes no `resources.assets`, e o `patch` grava as duas cópias. Ids repetidos recebem as chaves `13#2`, `13#3`; uma linha cujo inglês muda na segunda cópia ganha chave própria, `119@2`.

Algumas falas estão escritas direto no código C#, por exemplo "Your work is not done." ao tentar sair do escritório antes da hora. O IL2CPP guarda esses literais em `il2cpp_data/Metadata/global-metadata.dat`. Só os literais de `tools/maidloc/literals.json` são traduzidos: cada texto existe uma vez só e é compartilhado por todo o código, então a lista tem apenas textos exibidos que o código nunca compara. O `patch` grava o texto novo no fim do arquivo e aponta a tabela de literais para ele. Na primeira vez ele guarda um `global-metadata.dat.bak`, como o `resources.assets.bak`.
